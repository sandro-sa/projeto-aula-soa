Criar o módulo domínio e seus estados

Criar o módulo domínio, seus enums e a compilação Maven dentro do Eclipse.

1. O que fazer nesta etapa

A partir desta aula, o trabalho será feito no Eclipse. Sua tarefa é criar o módulo domínio, seus dois enums e conferir o POM pai:

  1. Criar o módulo Maven dominio dentro de restaurante-soap, com seu pom.xml.
  2. Conferir a entrada dominio no bloco modules de source/restaurante-soap/pom.xml.
  3. Criar SituacaoMesa.java e SituacaoPedido.java no pacote br.edu.soa.restaurante.dominio.

A aula termina quando a aba Console mostrar BUILD SUCCESS e o projeto dominio apresentar os dois enums.

Abra o workspace usado na aula 12. No Project Explorer, os projetos laboratorio-restaurante e restaurante-soap já devem estar importados. Os arquivos continuam fisicamente na sua pasta laboratorio-restaurante-soa.

2. Entenda o que será criado

O módulo dominio vai guardar os tipos do negócio. Começaremos com dois enums: tipos Java que definem uma lista de valores possíveis.

Estados usados no restaurante
Enum Valores Significado
SituacaoMesa LIVRE, OCUPADA Indica se a mesa pode receber um pedido ou já possui um pedido aberto.
SituacaoPedido ABERTO, FECHADO, CANCELADO Indica se o pedido está em andamento, foi encerrado ou cancelado.

Usar um enum permite ao compilador conferir esses valores, em vez de depender de textos digitados livremente. Nesta aula, vamos definir os estados; as regras para abrir, fechar e cancelar pedidos serão implementadas na aplicação.

POM pai e POM filho: o bloco parent faz o domínio herdar Java 17, codificação e configurações de build de restaurante-soap. Já o modules do pai inclui o domínio na execução do Maven. São relações diferentes. Consulte a referência dos POMs ou a definição de enum em Java 17.

3. Faça o passo a passo

Passo 1: Criar o módulo Maven no Eclipse

  1. No Project Explorer, selecione restaurante-soap, o projeto criado na aula 12.
  2. Acesse File → New → Other… → Maven → Maven Module → Next.
  3. Marque Create a simple project (skip archetype selection).
  4. Em Module Name, informe dominio.
  5. Em Parent Project, confira restaurante-soap. Use Browse… para selecioná-lo se necessário.
  6. Clique em Next e confira as informações abaixo. Depois, clique em Finish.
Dados do módulo
Campo Valor
Group Id br.edu.soa
Artifact Id dominio
Version 2.0.0, a versão do pai; no POM do próximo passo, ela será herdada.
Packaging jar

Confira: o projeto dominio deve aparecer no Eclipse, e sua pasta deve ficar em source/restaurante-soap/dominio, dentro do projeto pai. O assistente cria a estrutura inicial e registra o módulo; vamos conferir o conteúdo dos POMs nos próximos passos.

Se você já criou o módulo seguindo a versão anterior do roteiro, continue no projeto existente. Se a pasta ainda não estiver importada, use File → Import… → Maven → Existing Maven Projects e selecione source/restaurante-soap/dominio.

Passo 2: Conferir o POM do módulo domínio

No projeto dominio, dê dois cliques em pom.xml. Se o editor abrir uma visão de formulário, selecione a aba pom.xml para editar o XML.

Substitua o conteúdo gerado pelo bloco completo abaixo, incluindo os comentários, e salve com Ctrl+S:

<!-- Identifica o documento como um POM Maven; o esquema auxilia o editor. -->
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
  <!-- Formato do POM, como na aula 12. -->
  <modelVersion>4.0.0</modelVersion>

  <!-- Herda a configuração do POM source/restaurante-soap/pom.xml. -->
  <parent>
    <groupId>br.edu.soa</groupId>
    <artifactId>restaurante-soap</artifactId>
    <!-- Deve corresponder à versão declarada no POM pai. -->
    <version>2.0.0</version>
  </parent>

  <!-- Nome deste módulo. groupId e version são herdados do pai. -->
  <artifactId>dominio</artifactId>
  <!-- Na fase package, o artefato deste módulo será um arquivo JAR. -->
  <packaging>jar</packaging>

  <!-- Vazio: o domínio usa apenas Java, sem bibliotecas externas. -->
  <dependencies>
  </dependencies>
</project>

Confira: parent aponta para restaurante-soap, versão 2.0.0. Por padrão, o Maven procura esse pai em ../pom.xml, uma pasta acima. O módulo se chama dominio e suas dependências ficam vazias.

Passo 3: Registrar o domínio no POM pai

No projeto restaurante-soap, abra pom.xml e selecione a aba de edição XML.

O assistente de módulo acrescenta a entrada ao bloco modules. Confira se ela aparece uma única vez; se ainda estiver faltando, acrescente-a. O bloco deve ficar assim:

<modules>
    <module>dominio</module>
</modules>

Salve e mantenha as propriedades, as versões e os plugins da aula 12. No POM da raiz do laboratório, a lista continua apontando para source/restaurante-soap.

Depois, selecione os projetos restaurante-soap e dominio no Project Explorer, clique com o botão direito e use Maven → Update Project… → OK para atualizar a configuração.

Confira: o bloco alterado pertence ao POM source/restaurante-soap/pom.xml. O caminho dominio é relativo a ele.

Conferir o POM pai completo após a alteração

Esta é a versão completa esperada, com os comentários da aula 12. Use-a para comparar com seu arquivo:

<!-- project é a raiz do XML; xmlns identifica o formato de POM do Maven. -->
<project xmlns="http://maven.apache.org/POM/4.0.0">
  <!-- Versão do formato do POM. Não é a versão do Maven instalado. -->
  <modelVersion>4.0.0</modelVersion>
  <!-- Identifica o grupo da instituição/projeto nas coordenadas Maven. -->
  <groupId>br.edu.soa</groupId>
  <!-- Nome do POM pai que os futuros módulos SOAP vão herdar. -->
  <artifactId>restaurante-soap</artifactId>
  <!-- Versão adotada para os artefatos do restaurante neste material. -->
  <version>2.0.0</version>
  <!-- Este projeto organiza/configura outros projetos; não produz JAR ou WAR. -->
  <packaging>pom</packaging>
  <!-- Nesta etapa, o build inclui apenas o módulo dominio. -->
  <modules>
    <module>dominio</module>
  </modules>
  <!-- Valores reutilizáveis. A escrita ${nome} consulta uma propriedade. -->
  <properties>
    <!-- Compila fontes e APIs para Java 17. Não instala nem seleciona o JDK. -->
    <maven.compiler.release>17</maven.compiler.release>
    <!-- Preserva nomes de parâmetros no bytecode para uso por reflexão. -->
    <maven.compiler.parameters>true</maven.compiler.parameters>
    <!-- Padroniza a codificação dos arquivos-fonte, inclusive os acentos. -->
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
    <!-- Versão fixada da implementação SOAP Metro, usada em jaxws-rt. -->
    <metro.version>4.0.5</metro.version>
    <!-- Versão do catálogo de dependências (BOM) usado pelo projeto SOAP. -->
    <spring-boot.version>3.5.16</spring-boot.version>
  </properties>
  <!-- Define versões padrão. Cada módulo ainda declara as dependências que usa. -->
  <dependencyManagement>
    <dependencies>
      <dependency>
        <groupId>org.springframework.boot</groupId>
        <!-- BOM: catálogo que alinha versões do driver MySQL, Flyway e JUnit. -->
        <artifactId>spring-boot-dependencies</artifactId>
        <version>${spring-boot.version}</version>
        <!-- Importamos um documento POM de configuração. -->
        <type>pom</type>
        <!-- Incorpora o catálogo do BOM ao dependencyManagement deste projeto. -->
        <scope>import</scope>
      </dependency>
      <dependency>
        <groupId>com.sun.xml.ws</groupId>
        <!-- Implementação Metro que executa serviços e clientes SOAP. -->
        <artifactId>jaxws-rt</artifactId>
        <version>${metro.version}</version>
      </dependency>
      <dependency>
        <groupId>jakarta.xml.ws</groupId>
        <!-- API Jakarta XML Web Services: tipos como Service e Endpoint. -->
        <artifactId>jakarta.xml.ws-api</artifactId>
        <version>4.0.2</version>
      </dependency>
      <dependency>
        <groupId>jakarta.jws</groupId>
        <!-- API de anotações como WebService, WebMethod e WebParam. -->
        <artifactId>jakarta.jws-api</artifactId>
        <version>3.0.0</version>
      </dependency>
    </dependencies>
  </dependencyManagement>
  <!-- Configuração das ferramentas de compilação, testes e empacotamento. -->
  <build>
    <!-- Centraliza versões/opções de plugins usados pelos módulos; não agenda tarefas. -->
    <pluginManagement>
      <plugins>
        <plugin>
          <groupId>org.apache.maven.plugins</groupId>
          <!-- Compila o Java; lê maven.compiler.release e maven.compiler.parameters. -->
          <artifactId>maven-compiler-plugin</artifactId>
          <version>3.14.0</version>
        </plugin>
        <plugin>
          <groupId>org.apache.maven.plugins</groupId>
          <!-- Executa os testes unitários na fase test dos módulos com esse ciclo. -->
          <artifactId>maven-surefire-plugin</artifactId>
          <version>3.5.3</version>
          <!-- Opções específicas do plugin Surefire. -->
          <configuration>
            <!-- Usa classpath nos testes, conforme a organização sem JPMS deste laboratório. -->
            <useModulePath>false</useModulePath>
          </configuration>
        </plugin>
        <plugin>
          <groupId>org.apache.maven.plugins</groupId>
          <!-- Empacota a aplicação web em WAR para implantação no Tomcat. -->
          <artifactId>maven-war-plugin</artifactId>
          <version>3.4.0</version>
        </plugin>
        <plugin>
          <groupId>org.codehaus.mojo</groupId>
          <!-- Permite chamar uma classe main com exec:java, por exemplo a tela Swing. -->
          <artifactId>exec-maven-plugin</artifactId>
          <version>3.5.0</version>
        </plugin>
      </plugins>
    </pluginManagement>
    <!-- Declara plugins herdáveis; o Surefire usa a versão/opções definidas acima. -->
    <plugins>
      <plugin>
        <groupId>org.apache.maven.plugins</groupId>
        <!-- Executa os testes unitários na fase test dos módulos com esse ciclo. -->
        <artifactId>maven-surefire-plugin</artifactId>
      </plugin>
    </plugins>
  </build>
</project>

Passo 4: Criar SituacaoMesa.java

Primeiro, crie o pacote Java no módulo dominio:

  1. Expanda dominio e selecione src/main/java. Se a pasta não aparecer, clique com o botão direito no projeto, escolha New → Source Folder e informe src/main/java.
  2. Clique com o botão direito em src/main/java e escolha New → Package.
  3. Em Name, digite br.edu.soa.restaurante.dominio. Mantenha Create package-info.java desmarcado e clique em Finish.

Agora, crie o enum nesse pacote:

  1. Selecione br.edu.soa.restaurante.dominio e acesse File → New → Other… → Java → Enum.
  2. Confira Source folder: dominio/src/main/java, e Package: br.edu.soa.restaurante.dominio.
  3. Em Name, informe SituacaoMesa, mantenha o modificador public e clique em Finish.

Substitua o conteúdo gerado pelo código completo abaixo e salve com Ctrl+S:

// O pacote corresponde à pasta br/edu/soa/restaurante/dominio.
package br.edu.soa.restaurante.dominio;

// Enum: define os valores possíveis para a situação de uma mesa.
public enum SituacaoMesa {
    // A mesa pode receber um novo pedido.
    LIVRE,
    // A mesa possui um pedido aberto.
    OCUPADA
}

Confira: o nome do arquivo é SituacaoMesa.java, com as mesmas maiúsculas do enum. A declaração package é br.edu.soa.restaurante.dominio.

Referências dos assistentes: New Java Package e New Java Enum.

Passo 5: Criar SituacaoPedido.java

  1. Selecione novamente o pacote br.edu.soa.restaurante.dominio no projeto dominio.
  2. Acesse File → New → Other… → Java → Enum.
  3. Em Name, informe SituacaoPedido, confira o mesmo pacote e mantenha public.
  4. Clique em Finish. Substitua o conteúdo gerado pelo código abaixo e salve com Ctrl+S.
package br.edu.soa.restaurante.dominio;

// Enum: define os valores possíveis para a situação de um pedido.
public enum SituacaoPedido {
    // O pedido ainda pode receber alterações.
    ABERTO,
    // A conta foi encerrada.
    FECHADO,
    // O pedido foi cancelado.
    CANCELADO
}

Confira: os dois arquivos têm o mesmo pacote. public permite que os outros módulos usem esses tipos; enum define os nomes válidos. Os comentários explicam os estados, mas não executam mudanças no pedido.

Passo 6: Compilar pelo Eclipse

  1. Use File → Save All para salvar os arquivos abertos.
  2. No Project Explorer, clique com o botão direito em dominio e escolha Run As → Maven build….
  3. Em Name, informe Compilar dominio.
  4. Confira Base directory: deve ser a pasta source/restaurante-soap/dominio. Use Browse Workspace… e selecione o projeto dominio se precisar corrigir.
  5. Em Goals, digite apenas o conteúdo abaixo. Na aba JRE, selecione o JDK 17 registrado nas aulas anteriores.
compile

Clique em Apply e depois em Run. Acompanhe a execução na aba Console.

Deu certo quando: a compilação de dominio terminar com BUILD SUCCESS. O campo Goals recebe a fase do Maven, sem o prefixo mvn.

compile transforma os fontes .java em .class. O Maven gera SituacaoMesa.class e SituacaoPedido.class em source/restaurante-soap/dominio/target/classes/br/edu/soa/restaurante/dominio.

Passo 7: Conferir o projeto na IDE

  1. No Project Explorer, expanda dominio → src/main/java → br.edu.soa.restaurante.dominio.
  2. Confira os arquivos SituacaoMesa.java e SituacaoPedido.java. Abra cada um e compare o pacote e os valores com esta aula.
  3. Na aba Problems, confira se há erros referentes ao projeto dominio. Se a aba não estiver visível, use Window → Show View → Problems.

Confira: os dois enums estão no mesmo pacote, o projeto está sem erros de compilação e a aba Console registrou BUILD SUCCESS.

Se a criação ou a compilação no Eclipse não der certo
  • O Maven não encontra dominio: confira a linha <module>dominio</module> no POM SOAP e a existência de dominio/pom.xml.
  • O POM pai não é encontrado: confira groupId, artifactId e versão em parent. Eles devem corresponder ao POM de restaurante-soap.
  • Erro de nome ou pacote: confira as maiúsculas de SituacaoMesa e SituacaoPedido e a linha package br.edu.soa.restaurante.dominio;.
  • src/main/java não aparece: use Maven → Update Project…. Se necessário, crie a pasta com New → Source Folder no projeto dominio.
  • Falha ao resolver a propriedade de versão do Boot: preserve <spring-boot.version>3.5.16</spring-boot.version> no POM pai. O nome deve coincidir com ${spring-boot.version}.
  • O build usa a pasta errada: na configuração Maven build, confira se Base directory aponta para dominio e se Goals contém apenas compile.
  • Java 17 não foi reconhecido: confira o JDK na aba JRE da configuração de execução e em Window → Preferences → Java → Installed JREs.

5. Confira e continue

  • Criei o POM de dominio com o pai restaurante-soap.
  • Registrei apenas dominio no bloco modules do POM SOAP.
  • Salvei os dois enums no pacote e nos arquivos indicados.
  • Executei Run As → Maven build… com compile e a aba Console mostrou BUILD SUCCESS.
  • O novo módulo e seus arquivos aparecem no Eclipse.

Depois, avance para Implementar Mesa, onde usaremos o enum SituacaoMesa.

  • [R06] Guilherme Silveira; Mário Amaral — Java SE 7 Programmer I: o guia para sua certificação Oracle Certified Associate. Cap. 3, §3.2: estrutura da classe e pacotes. Páginas 18–20 do PDF.
