2. Entenda o que será feito

Problema no sistema

As regras podem funcionar com um repositório simulado e ainda falhar ao gravar, reverter ou disputar uma mesa no banco. A suíte separa a integração SQL, a classificação de erros e a verificação opcional com o MySQL local.

Os cenários verificam transações, histórico e concorrência com H2 e classificam os códigos de erro MySQL.

  • MySqlLocalTest é opt-in: exige MYSQL_TEST_URL para restaurante_teste em localhost e MYSQL_TEST_USER; MYSQL_TEST_PASSWORD pode estar ausente somente quando o código usar getOrDefault e a conta de laboratório estiver sem senha.
  • Para habilitá-lo, primeiro crie o banco e o usuário de teste no XAMPP, depois configure Environment na mesma execução Maven do Eclipse.
  • H2 em modo MySQL não comprova uma execução no servidor MySQL real.
Pontos para observar no código
  • Os 18 testes comportamentais usam bancos H2 independentes por teste.
  • ErrosMySqlTest verifica códigos específicos mesmo quando SQLState é igual.
  • MySqlLocalTest faz uma conta de 110,00 no banco real e a relê por outro repositório; depende de configuração explícita.

3. Preparar o banco de testes no XAMPP (MySQL/MariaDB)

Antes de executar o teste opcional: mantenha o módulo de banco de dados iniciado no painel XAMPP e prepare um banco separado chamado restaurante_teste. A preparação abaixo é exclusiva para laboratório local; não use contas sem senha em servidores de produção, compartilhados ou acessíveis pela rede.

Passo A: identificar o servidor e a porta no phpMyAdmin

  1. No XAMPP Control Panel, inicie o módulo MySQL e clique em Admin.
  2. No phpMyAdmin, abra a aba SQL e execute a consulta a seguir.
  3. Anote a versão e a porta. O painel do XAMPP pode fornecer MariaDB em vez de MySQL; nesse caso, o nome exibido no painel não comprova que o servidor seja MySQL 8.4.
SELECT VERSION() AS versao_banco,
       @@version_comment AS tipo_servidor,
       @@port AS porta;

O teste Java original aceita URLs com localhost:3306 ou localhost:13306. Se a porta exibida for diferente, ajuste também a expressão da anotação @EnabledIfEnvironmentVariable no arquivo de teste, antes de executar.

Passo B: criar o banco e um usuário dedicado sem senha (somente localhost)

Na aba SQL do phpMyAdmin, conectado como administrador, execute o script abaixo. Ele mantém intacta a senha do usuário restaurante utilizado pelos outros bancos, criando uma conta própria restaurante_tester para a aula.

-- LABORATÓRIO LOCAL SOMENTE: não use sem senha em produção.
CREATE DATABASE IF NOT EXISTS restaurante_teste
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

-- Conta separada para testes; se já existir, o ALTER redefine sua senha vazia.
CREATE USER IF NOT EXISTS 'restaurante_tester'@'localhost'
  IDENTIFIED BY '';
ALTER USER 'restaurante_tester'@'localhost'
  IDENTIFIED BY '';

GRANT SELECT, INSERT, UPDATE, DELETE,
      CREATE, ALTER, INDEX, REFERENCES
ON restaurante_teste.*
TO 'restaurante_tester'@'localhost';

-- Conferência: privilégios restritos ao banco de teste.
SHOW GRANTS FOR 'restaurante_tester'@'localhost';

Explicação: CREATE DATABASE cria um banco isolado; CREATE USER e ALTER USER deixam a senha vazia apenas na conta de laboratório; GRANT limita os privilégios ao banco restaurante_teste. Não é necessário criar manualmente as tabelas de domínio, pois Banco.configurar(...) aplica a migração V1__restaurante.sql por Flyway.

Segurança: o host localhost restringe a identidade da conta ao acesso local, mas não substitui uma senha e não garante, sozinho, que o servidor esteja inacessível pela rede. Prefira uma senha forte sempre que possível. Caso já tenha atribuído uma senha vazia ao usuário restaurante, restaure uma senha segura naquela conta separadamente.

Passo C: configurar as variáveis de ambiente da execução Maven no Eclipse

  1. Acesse Run → Run Configurations… → Maven Build e selecione a configuração específica da aula 32.
  2. Na aba Environment, use New…/Add… e preencha os dois valores da tabela.
  3. Não precisa criar MYSQL_TEST_PASSWORD na interface quando você aplicar a alteração de código abaixo: se a variável estiver ausente, o teste utilizará uma string vazia.
  4. Clique em Apply e execute essa mesma configuração com o botão Run, para não perder as variáveis.

Passo D: executar os testes corretamente

Na aba Main, selecione como Base directory a pasta source/restaurante-soap, que contém o pom.xml agregador. Confira o JDK 17 na aba JRE. No campo Goals, informe somente:

-pl :infraestrutura -am test

Não escreva mvn no campo Goals: a IDE já chama o Maven. No PowerShell, fora do Eclipse, a forma equivalente é mvn -pl :infraestrutura -am test executada a partir da pasta agregadora, com as variáveis disponibilizadas naquele processo.

Para executar apenas o teste real em uma segunda rodada, altere temporariamente o campo Goals para:

-pl :infraestrutura -am test -Dtest=MySqlLocalTest -Dsurefire.failIfNoSpecifiedTests=false

import java.sql.SQLException;

    // Cenário: distingue duplicado de chave estrangeira no mesmo sql state.
    @Test void distingueDuplicadoDeChaveEstrangeiraNoMesmoSqlState() {
        assertEquals("DUPLICADO",JdbcRepositorio.falhaSql(new SQLException("Detalhe privado","23000",1062)).codigo());
        for (int codigo : new int[]{1451,1452})
            assertEquals("REFERENCIADO",JdbcRepositorio.falhaSql(new SQLException("Detalhe privado","23000",codigo)).codigo());
    }
    // Cenário: lock timeout edeadlock pedem nova tentativa.
    @Test void lockTimeoutEDeadlockPedemNovaTentativa() {
        for (int codigo : new int[]{1205,1213})
            assertEquals("CONCORRENCIA",JdbcRepositorio.falhaSql(new SQLException("Detalhe privado","HY000",codigo)).codigo());
    }
}

/** Opt-in: usa apenas banco de teste explícito no MySQL localhost. Não apaga tabelas. */
@EnabledIfEnvironmentVariable(named="MYSQL_TEST_URL",matches="jdbc:mysql://localhost:(?:3306|13306)/restaurante_teste(?:\\?.*)?")
class MySqlLocalTest {
    // Cenário: persiste conta no my sql real.
    @Test void persisteContaNoMySqlReal() {
        var ds=Banco.configurar(System.getenv("MYSQL_TEST_URL"),System.getenv("MYSQL_TEST_USER"),System.getenv().getOrDefault("MYSQL_TEST_PASSWORD", ""));
        var api=new Restaurante(new JdbcRepositorio(ds));
        var usados=api.listarMesas().stream().map(m -> m.numero()).collect(java.util.stream.Collectors.toSet());
        int numero=java.util.stream.IntStream.range(1000,10000).filter(n -> !usados.contains(n)).findFirst().orElseThrow();
        var mesa=api.salvarMesa(0,numero);
        var cat=api.salvarCategoria(0,"Teste MySQL","Dados de integração",true);
        var produto=api.salvarProduto(0,cat.id(),"Carbonara de teste","","",new BigDecimal("55.00"),"1 pessoa",true);
        var pedido=api.adicionarItem(api.abrirPedido(mesa.id()).id(),produto.id(),2);
        assertEquals(new BigDecimal("110.00"),pedido.total());
        api.fecharPedido(pedido.id());
        var outraInstancia=new Restaurante(new JdbcRepositorio(ds));
        assertEquals(new BigDecimal("110.00"),outraInstancia.consultarPedido(pedido.id()).total());
        assertEquals(br.edu.soa.restaurante.dominio.SituacaoMesa.LIVRE,outraInstancia.consultarMesa(mesa.id()).situacao());
    }
}

Melhoria para XAMPP sem senha: na chamada de Banco.configurar, use System.getenv().getOrDefault("MYSQL_TEST_PASSWORD", ""). Assim, quando a variável não existir no Eclipse, o Java fornecerá "", evitando null. Isso não elimina a necessidade de configurar MYSQL_TEST_URL e MYSQL_TEST_USER.

A anotação @EnabledIfEnvironmentVariable permanece intencionalmente ativa: é uma trava que impede a execução acidental no banco errado. Skipped: 1 significa que ela não foi satisfeita.

Fundamentação nos PDFs fornecidos

Teste as consequências de concorrência e falhas transacionais, não apenas métodos isolados. O comportamento em H2 e o comportamento no MySQL real são evidências distintas; um teste opt-in ignorado não prova a segunda.

  • [R08] Hébert Coelho — JPA Eficaz: as melhores práticas de persistência de dados em Java. Cap. 8, §8.4: versionamento e locks. Páginas 159–164 do PDF.
