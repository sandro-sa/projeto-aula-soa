2. Entenda o que será feito

Problema no sistema

Uma gravação feita por outro caminho também precisa respeitar o histórico e os vínculos dos pedidos. A migração cria tabelas e restrições que reforçam esses invariantes no banco.

O arquivo versiona tabelas, chaves e restrições. Flyway aplicará a migração quando Banco for configurado.

  • O nome tem dois sublinhados depois de V1.
  • Em banco que já recebeu V1, preserve o arquivo aplicado e faça novas mudanças em V2.
Pontos para observar no código
  • As cinco tabelas usam InnoDB; PKs e FKs têm tipos compatíveis.
  • NUMERIC(9,2) limita preço a centavos; CHECK reforça quantidade e estados.
  • Exclusões não têm cascade, preservando histórico.
  • Em um banco já migrado, uma alteração nova exige V2; não edite V1 aplicada.

Passo 2: Criar V1__restaurante.sql

Caminho na pasta do laboratório: source/restaurante-soap/infraestrutura/src/main/resources/db/migration/V1__restaurante.sql.

O caminho começa na pasta do laboratório. No Eclipse, trabalhe no projeto infraestrutura, criado na aula 27. src/main/resources guarda os arquivos que o Maven inclui no classpath. As pastas db e migration organizam os scripts que o Flyway localizará.

  1. No Project Explorer, expanda o projeto infraestrutura e procure src/main/resources. Se essa pasta já aparecer, use-a no próximo passo. Se estiver faltando, selecione o projeto e abra File → New → Other… → General → Folder → Next. Em Enter or select the parent folder, selecione infraestrutura. Em Folder name, digite src/main/resources e clique em Finish.
  2. Selecione src/main/resources e use File → New → Other… → General → Folder → Next. Confira a pasta pai infraestrutura/src/main/resources, informe db em Folder name e clique em Finish.
  3. Selecione a pasta db que acabou de criar. Repita o assistente General → Folder, informe migration e finalize. Confira a pasta infraestrutura/src/main/resources/db/migration.

-- Finalidade: Criar db/migration/V1__restaurante.sql nos recursos da infraestrutura.
CREATE TABLE mesa (
 id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY,
 numero INTEGER NOT NULL UNIQUE CHECK (numero BETWEEN 1 AND 9999),
 situacao VARCHAR(20) NOT NULL DEFAULT 'LIVRE' CHECK (situacao IN ('LIVRE','OCUPADA'))
) ENGINE=InnoDB;
CREATE TABLE categoria (
 id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY,
 nome VARCHAR(120) NOT NULL,
 descricao VARCHAR(2000) NOT NULL,
 ativo BOOLEAN NOT NULL
) ENGINE=InnoDB;
CREATE TABLE produto (
 id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY,
 categoria_id BIGINT NOT NULL,
 nome VARCHAR(160) NOT NULL,
 descricao VARCHAR(2000) NOT NULL,
 imagem VARCHAR(1000) NOT NULL,
 preco NUMERIC(9,2) NOT NULL CHECK (preco >= 0),
 porcao VARCHAR(160) NOT NULL,
 disponivel BOOLEAN NOT NULL,
 CONSTRAINT fk_produto_categoria FOREIGN KEY (categoria_id) REFERENCES categoria(id)
) ENGINE=InnoDB;
CREATE TABLE pedido (
 id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY,
 mesa_id BIGINT NOT NULL,
 data_hora DATETIME(6) NOT NULL,
 situacao VARCHAR(20) NOT NULL CHECK (situacao IN ('ABERTO','FECHADO','CANCELADO')),
 CONSTRAINT fk_pedido_mesa FOREIGN KEY (mesa_id) REFERENCES mesa(id),
 CONSTRAINT fk_pedido_aberta FOREIGN KEY (mesa_aberta) REFERENCES mesa(id),
 mesa_aberta BIGINT UNIQUE,
 CHECK ((situacao = 'ABERTO' AND mesa_aberta IS NOT NULL AND mesa_aberta = mesa_id)
     OR (situacao <> 'ABERTO' AND mesa_aberta IS NULL))
) ENGINE=InnoDB;
CREATE TABLE item_pedido (
 id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY,
 pedido_id BIGINT NOT NULL,
 produto_id BIGINT NOT NULL,
 nome_produto VARCHAR(160) NOT NULL,
 quantidade INTEGER NOT NULL CHECK (quantidade BETWEEN 1 AND 10000),
 preco_unitario NUMERIC(9,2) NOT NULL CHECK (preco_unitario >= 0),
 CONSTRAINT fk_item_pedido FOREIGN KEY (pedido_id) REFERENCES pedido(id),
 CONSTRAINT fk_item_produto FOREIGN KEY (produto_id) REFERENCES produto(id)
) ENGINE=InnoDB;
CREATE INDEX ix_produto_categoria ON produto(categoria_id);
CREATE INDEX ix_pedido_mesa ON pedido(mesa_id);
CREATE INDEX ix_item_pedido ON item_pedido(pedido_id);
CREATE INDEX ix_item_produto ON item_pedido(produto_id);

Entenda cada parte de V1__restaurante.sql
Parte O que faz e por que importa
V1__restaurante.sql O nome identifica a primeira migração. Flyway registra sua aplicação quando o banco é preparado pela infraestrutura.
mesa A chave id identifica o registro. numero é único e tem intervalo permitido. situacao registra LIVRE ou OCUPADA.
categoria e produto categoria_id liga o produto a uma categoria existente. preco usa NUMERIC com duas casas e restrição de valor não negativo.
pedido e mesa_aberta mesa_id preserva o vínculo histórico. mesa_aberta só é preenchida durante a abertura. Seu UNIQUE impede dois pedidos abertos para a mesma mesa.
item_pedido Vincula item a pedido e produto. Guarda quantidade, nome e preço unitário da inclusão, preservando os dados da venda.
FOREIGN KEY, CHECK e índices As chaves protegem referências e CHECK limita valores ou combinações. Os índices ajudam as consultas pelas relações entre tabelas.
