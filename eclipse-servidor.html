10. Desenhar as fronteiras SOA

Registrar Tomcat no Eclipse

Registrar o runtime do Tomcat, configurar o JDK 17 e validar o servidor sem um projeto Java.

1. Objetivo da aula

Registrar o runtime do Tomcat, configurar o JDK 17 e validar o servidor sem um projeto Java.

2. Implementação passo a passo e código da etapa

Passo 1: Instalar o suporte Tomcat no Eclipse

Para administrar o Tomcat diretamente no Eclipse, é necessário possuir as ferramentas de desenvolvimento web e integração com servidores.

  1. Abra o Eclipse.
  2. Acesse o menu Help > Eclipse Marketplace.
  3. Pesquise por ferramentas do Eclipse Web Tools Platform (WTP) e suporte a servidores Java.
  4. Se necessário, utilize Help > Install New Software para instalar os componentes Web Tools e os adaptadores de servidor.
  5. Reinicie o Eclipse após a instalação.
  6. Caso o suporte não esteja disponível, considere utilizar a distribuição Eclipse IDE for Enterprise Java and Web Developers.

O nome e a disponibilidade dos componentes podem variar conforme a versão do Eclipse.

Passo 2: Configurar o Tomcat no Eclipse

  1. Abra o Eclipse.
  2. Acesse Window > Preferences.
  3. Localize Server > Runtime Environments.
  4. Clique em Add.
  5. Selecione Apache > Apache Tomcat v10.1, caso esteja disponível.
  6. Clique em Next.
  7. Informe o diretório de instalação: C:\Servers\apache-tomcat-10.1.61.
  8. Selecione a instalação do JDK 17.
  9. Clique em Finish.

Caso a opção Server não apareça, verifique a instalação dos componentes WTP e dos adaptadores de servidor.

Passo 3: Criar o servidor na aba Servers

  1. Acesse Window > Show View > Other.
  2. Procure por Server > Servers.
  3. Na aba Servers, clique com o botão direito e escolha New > Server.
  4. Selecione o Tomcat 10.1 configurado.
  5. Escolha o runtime correspondente.
  6. Clique em Finish.
  7. Clique com o botão direito no servidor e selecione Start.

Verifique no Console do Eclipse se o Tomcat iniciou corretamente.

Atenção: não inicie simultaneamente o mesmo Tomcat pelo PowerShell e pelo Eclipse utilizando as mesmas portas.

Passo 4: Iniciar o Tomcat pelo Eclipse

Nesta aula ainda não existe um projeto Java para publicar. Vamos verificar somente se o servidor Tomcat está corretamente integrado ao Eclipse.

  1. Na aba Servers, selecione o servidor Apache Tomcat v10.1.
  2. Confirme que o status inicial é Stopped.
  3. Clique com o botão direito no servidor e selecione Start.
  4. Abra a aba Console para acompanhar as mensagens.
  5. Verifique se o servidor mudou para o estado Started.

Se a porta 8080 já estiver ocupada, confira se outra instância do Tomcat foi iniciada pelo PowerShell antes de tentar novamente.

Passo 5: Testar o servidor sem uma aplicação

Abra http://localhost:8080/ no navegador. O resultado depende da configuração da instância criada pelo Eclipse: a página inicial do Tomcat poderá ser exibida ou a raiz poderá retornar HTTP 404, caso não exista uma aplicação ROOT publicada. Um erro 404 na raiz, isoladamente, não significa que o Tomcat falhou.

  1. Confira na aba Servers se o estado é Started.
  2. Confira no Console se há erros de inicialização.
  3. Verifique se o navegador conseguiu se conectar à porta configurada.
  4. Não tente acessar endpoints SOAP nem arquivos WSDL: eles ainda não foram criados.

Passo 6: Identificar CATALINA_HOME e CATALINA_BASE

O CATALINA_HOME aponta para os arquivos de instalação do Tomcat. Já CATALINA_BASE aponta para os arquivos de configuração e execução de uma instância específica. O Eclipse pode criar uma base separada para o servidor configurado na IDE.

  1. Na aba Servers, dê dois cliques no servidor.
  2. Observe a seção Server Locations, quando disponível.
  3. Abra as configurações de execução ou a visualização Console para inspecionar os caminhos utilizados.
  4. Compare os caminhos da instalação e da instância, sem alterar ou apagar arquivos.

Isso explica por que o Tomcat iniciado pelo Eclipse pode ter configurações e aplicações diferentes do Tomcat iniciado pelos scripts em C:\Servers\apache-tomcat-10.1.x\bin.

Passo 7: Parar o servidor e concluir a preparação

  1. Na aba Servers, clique com o botão direito no Tomcat.
  2. Selecione Stop.
  3. Aguarde até que o estado mude para Stopped.
  4. Não adicione módulos: a aplicação Restaurante será criada nas próximas aulas.

Checkpoint: Tomcat registrado no Eclipse, JDK 17 selecionado, servidor iniciado e interrompido sem erros críticos. Nenhum WAR é necessário.

6. Explicação do código e das decisões

  • O empacotamento WAR e a publicação de serviços serão ensinados apenas depois da criação dos módulos Maven.
  • JRE do runtime Tomcat pode ser 17 mesmo quando o Eclipse exige um JDK superior.
  • No estado Stopped é possível editar portas sem conflito com processos em execução.

Fundamentação nos PDFs fornecidos

O endereço concreto de um serviço liga protocolo, host, porta e contexto. Tomcat e o runtime do Eclipse ainda são preparação: um endereço no contrato não significa que o endpoint já exista. Os comandos Tomcat 10.1 são a adaptação deste laboratório.

7. Como implementar no Eclipse e executar

8. Fluxo da execução

Eclipse Servers → runtime Tomcat e JDK 17 → iniciar → conferir Console e porta HTTP → parar.

9. Resultado esperado nesta etapa

Runtime registrado, Tomcat iniciado e testado, e servidor novamente parado. Nenhum projeto ou WAR foi criado nesta aula.

O resultado é um checkpoint para você executar. O registro de validação do material distingue testes automatizados, reconstrução da trilha e execução real no MySQL. Consulte também a revisão passo a passo dos HTMLs.

10. Problemas frequentes

  • Tomcat não aparece na lista: confirme a instalação do Eclipse WTP e do adaptador do Tomcat.
  • Porta 8080 ocupada: verifique outras instâncias do Tomcat e serviços locais.
  • Não execute uma aula posterior para compensar um erro: retorne ao último checkpoint aprovado.

11. Checkpoint antes de continuar

  • Localizar a configuração de runtime e o JDK do servidor.
  • Não adicionar um projeto que ainda não existe.

12. Exercício

Localize CATALINA_BASE da instância Eclipse e compare com CATALINA_HOME da instalação.
