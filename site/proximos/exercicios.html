Continue no Eclipse após Resolver problemas do laboratório. Use os projetos e os arquivos que você construiu nas etapas anteriores.

2. Entenda o que será feito

Problema no sistema

Um laboratório reproduzível precisa demonstrar tanto os fluxos válidos quanto as recusas. A conclusão reúne evidências e permite escolher uma extensão com um resultado verificável.

Entenda os componentes desta etapa
ParteO que faz e por que importa
Maven verify e relatóriosUse o build da raiz para conferir os módulos e leia os resultados dos testes habilitados. Identifique separadamente os testes ignorados.
cenário no navegador e no SwingRegistre o cadastro, o pedido, o total e o estado após fechar, com evidências dos dois transportes.
casos de erroMostre o que o consumidor recebe para entrada inválida, papel insuficiente ou alteração de uma conta encerrada.
extensãoDefina o problema e a camada afetada. Escreva como reproduzir o caso e qual resultado provará que a extensão funcionou.

A entrega demonstra regras, integração e limites; uma extensão deve preservar contratos e histórico.

  • Separe testes automáticos, testes ignorados e verificação manual no MySQL.
  • Consulte a solução de referência somente como conferência do trabalho concluído.
Pontos para observar no código
  • As atividades percorrem regras de identidade, estado, dinheiro, concorrência e segurança.
  • Uma extensão deve produzir evidência nova e manter testes relevantes aprovados.

3. Faça o passo a passo

Passo 1: Verificar pelo Maven no Eclipse

  1. Use File → Save All.
  2. No projeto laboratorio-restaurante, clique com o botão direito e escolha Run As → Maven build…. Use um nome identificável, como Verificar aula 85.
  3. Confira Base directory: selecione o projeto laboratorio-restaurante com Browse Workspace…. Em Goals, informe o conteúdo abaixo, sem o prefixo mvn.
  4. Na aba JRE, confira o JDK 17. Clique em Apply → Run e acompanhe a aba Console.
clean verify

Confira: a execução deve terminar em BUILD SUCCESS. Leia também os relatórios em target/surefire-reports dos módulos executados e diferencie testes ignorados de aprovados.

Passo 2: Executar a atividade e registrar a evidência

  1. Execute a verificação Maven da raiz e examine os relatórios dos módulos.
  2. No registro do laboratório, reúna as evidências de preço histórico, mesa ocupada, pedido fechado, concorrência, autorização e persistência no MySQL.
  3. Identifique quais testes foram automatizados, quais foram manuais e quais ficaram ignorados ou pendentes.
  4. Escolha uma extensão, como paginação no SQL ou links de transição na API. Defina o comportamento esperado e os testes necessários antes de alterar o projeto.

Registre a verificação no arquivo docs/registro-laboratorio.md. No projeto laboratorio-restaurante, use New → File se ele ainda não existir; nas próximas atividades, acrescente a nova aula ao mesmo registro.

4. Resultado esperado

Seu registro aponta o que foi executado, os resultados e o plano de uma extensão.

Se a verificação não der certo
  • Leia a mensagem específica na Console ou na aba Problems; confira o projeto, o caminho do arquivo e o pacote.
  • Depois de mudar POMs, use Maven → Update Project…. Confira se cada módulo listado já possui seu POM.
  • No Maven build, confira Base directory, Goals e o JDK 17. Em erro de download, confira a conexão e o repositório informado.
  • Em problema de execução, diferencie configuração do processo, conexão com o banco, rota/contrato e regra de negócio. Consulte a aula de diagnóstico.
