2. Entenda o que será feito

Problema no sistema

Uma mesa com pedido aberto precisa manter seu número e sua identidade até a conta ser encerrada. Os clientes SOAP e REST vão usar as mesmas regras de cadastro, consulta e exclusão de mesas.

A aplicação recebe Repositorio no construtor e concentra as regras que devem valer para qualquer cliente.

  • Número de mesa deve estar entre 1 e 9999.
  • Mesa ocupada não pode ser renumerada ou excluída.
Pontos para observar no código
  • O construtor recebe Repositorio, sem saber quem o implementará.
  • Cada operação que lê/grava usa transacao; exceções impedem confirmação parcial.
  • As validações desta etapa ocorrem antes de criar entidades ou acessar o repositório.

Confira o enum SituacaoMesa antes de compilar

No projeto dominio, abra src/main/java → br.edu.soa.restaurante.dominio → SituacaoMesa.java. O enum da aula 13 deve declarar LIVRE e OCUPADA. A classe Restaurante usa OCUPADA para bloquear a alteração ou a exclusão de uma mesa com pedido aberto.

Corrigir “OCUPADA cannot be resolved or is not a field” no Eclipse
  1. Em Restaurante.java, coloque o cursor em SituacaoMesa na expressão SituacaoMesa.OCUPADA e pressione F3. Isso abre a declaração que o Eclipse está usando.

// Finalidade: Coordenar os casos de uso do restaurante pela porta Repositorio.
package br.edu.soa.restaurante.aplicacao;

import br.edu.soa.restaurante.dominio.*;
import java.math.BigDecimal;
import java.math.RoundingMode;
import java.net.URI;
import java.util.List;
import java.util.function.Function;

/** Casos de uso. O transporte não fornece total, preço de item nem situação do pedido. */
public final class Restaurante {
    private final Repositorio repositorio;

    public Restaurante(Repositorio repositorio) { this.repositorio = repositorio; }

    // Consulta as mesas pela porta de persistência.
    public List<Mesa> listarMesas() { return repositorio.transacao(Repositorio.Sessao::mesas); }
    // Obtém uma mesa identificada pelo ID.
    public Mesa consultarMesa(long id) { return repositorio.transacao(s -> s.mesa(id, false)); }
    // Valida o cadastro e impede alterar uma mesa ocupada.
    public Mesa salvarMesa(long id, int numero) {
        if (id < 0 || numero < 1 || numero > 9999) throw Falha.invalido("Número da mesa entre 1 e 9999; ID não negativo.");
        return repositorio.transacao(s -> {
            if (id > 0 && s.mesa(id, true).situacao() == SituacaoMesa.OCUPADA)
                throw Falha.conflito("MESA_OCUPADA", "Libere a mesa antes de alterar seu número.");
            return s.salvarMesa(id, numero);
        });
    }
    // Confere a situação da mesa antes de solicitar a exclusão.
    public void excluirMesa(long id) {
        repositorio.transacao(s -> {
            if (s.mesa(id, true).situacao() == SituacaoMesa.OCUPADA)
                throw Falha.conflito("MESA_OCUPADA", "Mesa possui pedido aberto.");
            s.excluirMesa(id); return null;
        });
    }
}

Confira: o arquivo pertence ao projeto aplicacao, no caminho indicado e com o conteúdo completo desta etapa.

Entenda cada parte de Restaurante.java

Módulo aplicacao · Pacote br.edu.soa.restaurante.aplicacao · Fontes src/main/java.

ParteO que faz e por que importa
campo repositorio e construtorRecebem a implementação da porta Repositorio. A classe coordena as decisões e usa a interface para ler e gravar.
listarMesas e consultarMesaA primeira operação lista o cadastro e a segunda busca uma mesa por ID. A consulta simples usa bloquear=false.
salvarMesaConfere ID e número antes de gravar. O ID zero representa um cadastro novo. Para um ID existente, consulta a mesa com bloqueio e recusa a alteração se ela estiver ocupada.
excluirMesaConfere a ocupação na mesma transação que executa a exclusão. Uma mesa ocupada produz a falha MESA_OCUPADA.
Falha.invalido e Falha.conflitoDiferenciam um número fora do intervalo de uma operação incompatível com o estado da mesa.
