2. Entenda o que será feito

Problema no sistema

A tela de cadastro precisa chamar mesas pelo contrato de rede. O WSDL estabelece como enviar um número de mesa, consultar por ID e receber uma falha de negócio.

O WSDL descreve mensagens, operações, binding SOAP e o endereço de MesaService.

  • O endereço escrito no WSDL não significa que o servidor já esteja publicado.
  • Os nomes e namespaces deverão coincidir com as classes e os descritores do servidor.
Pontos para observar no código
  • O serviço MesaService tem uma porta MesaPort.
  • O endereço localhost será usado quando o servidor for publicado; o desktop poderá substituí-lo.
  • Cada operação declara ErroNegocio para recusas de negócio previsíveis.

Entenda cada parte de MesaService.wsdl
ParteO que faz e por que importa
definitions e namespaceIdentificam MesaService no vocabulário do contrato do restaurante.
types e xs:importReferenciam restaurante.xsd. O caminho relativo permite que os quatro serviços usem a mesma definição de tipos.
message e partConectam as mensagens de operação aos elementos XML definidos no esquema.
portType / operation / input / outputDeclara criarMesa, consultarMesa, listarMesas, atualizarMesa e excluirMesa. A atualização combina o ID existente com MesaEntrada.
fault e ErroNegocioDeclaram que a operação pode retornar uma falha de negócio com detalhe estruturado.
binding e soap:bodyRelacionam as operações abstratas ao protocolo SOAP e à representação XML de suas mensagens.
service / port / soap:addressIdentificam a porta e publicam o endereço esperado /restaurante/soap/mesas. A implantação do WAR disponibiliza esse endereço.

No contrato de Mesa, identifique mensagem de entrada, saída e Fault, ligue as operações ao binding document/literal e confira service/port. O WSDL é escrito antes do endpoint: gerar uma interface Java não publica o serviço.
