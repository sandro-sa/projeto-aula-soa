Criar o módulo WAR do servidor

Criar o módulo servidor com empacotamento WAR e dependências do núcleo e do contrato.

1. O que fazer nesta etapa

Criar o módulo servidor com empacotamento WAR e dependências do núcleo e do contrato.

  1. Criar: source/restaurante-soap/servidor/pom.xml
  2. Atualizar: source/restaurante-soap/pom.xml

A aula termina quando: O módulo servidor e seu POM compilam com os módulos que já existem.

Continue no Eclipse após Gerar Java a partir dos contratos. Use os projetos e os arquivos que você construiu nas etapas anteriores.

2. Entenda o que será feito

O WAR reúne o runtime SOAP e a integração com Servlet para publicação no Tomcat.

  • A API Servlet tem escopo provided porque será oferecida pelo Tomcat.
  • Os endpoints e descritores serão acrescentados nas próximas aulas.
Pontos para observar no código
  • contextInitialized compõe o grafo; contextDestroyed remove referências ao encerrar a aplicação.
  • Acesso.executar recebe Supplier, devolve o resultado e concentra a tradução segura de exceções.
  • @Resource injeta o contexto da chamada, que permite verificar o papel do usuário.
  • @WebService aponta para a interface gerada e para serviço/porta definidos no WSDL.

3. Faça o passo a passo

Passo 1: Preparar o novo módulo na IDE

Primeiro, crie o módulo servidor no Eclipse:

  1. Selecione restaurante-soap e use File → New → Other… → Maven → Maven Module.
  2. Marque Create a simple project, informe Module Name servidor e confira Parent Project restaurante-soap.
  3. Confira Group Id br.edu.soa, Artifact Id servidor, versão 2.0.0 e Packaging war. Finalize e confira a pasta source/restaurante-soap/servidor.
  4. O assistente registra o módulo; compare os POMs abaixo e mantenha uma única entrada por módulo.

Se o módulo já existir, abra o projeto existente e revise os arquivos.

Passo 2: Criar pom.xml

Caminho na pasta do laboratório: source/restaurante-soap/servidor/pom.xml.

  1. No projeto servidor, selecione a raiz do projeto.
  2. Use File → New → Other… → General → File, informe pom.xml e confira o diretório de destino.
  3. Abra o arquivo no editor de texto/código do Eclipse e salve em UTF-8. Para XML e POM, selecione a aba de fonte do editor quando houver uma visão de formulário.

Os comentários do código explicam os blocos e podem ser copiados junto com o arquivo. Salve com Ctrl+S.

<!-- Finalidade: Configurar o módulo e suas dependências. -->
<project xmlns="http://maven.apache.org/POM/4.0.0" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
  <!-- Versão do formato do documento POM, não do Maven instalado. -->
  <modelVersion>4.0.0</modelVersion>
  <!-- Herda a configuração do POM identificado por estas coordenadas. -->
  <parent>
    <groupId>br.edu.soa</groupId>
    <artifactId>restaurante-soap</artifactId>
    <version>2.0.0</version>
  </parent>
  <artifactId>servidor</artifactId>
  <packaging>war</packaging>
  <dependencies>
    <dependency>
      <groupId>br.edu.soa</groupId>
      <artifactId>contrato</artifactId>
      <version>${project.version}</version>
    </dependency>
    <dependency>
      <groupId>br.edu.soa</groupId>
      <artifactId>infraestrutura</artifactId>
      <version>${project.version}</version>
    </dependency>
    <dependency>
      <groupId>com.sun.xml.ws</groupId>
      <!-- Runtime Metro utilizado por serviços e clientes SOAP. -->
      <artifactId>jaxws-rt</artifactId>
    </dependency>
    <dependency>
      <groupId>jakarta.servlet</groupId>
      <!-- API Servlet oferecida pelo Tomcat na implantação. -->
      <artifactId>jakarta.servlet-api</artifactId>
      <scope>provided</scope>
    </dependency>
    <dependency>
      <groupId>com.fasterxml.jackson.core</groupId>
      <artifactId>jackson-databind</artifactId>
    </dependency>
    <dependency>
      <groupId>com.h2database</groupId>
      <!-- Banco em memória usado pelos testes; não equivale a validar MySQL Server. -->
      <artifactId>h2</artifactId>
      <scope>test</scope>
    </dependency>
    <dependency>
      <groupId>org.junit.jupiter</groupId>
      <!-- API e suporte dos testes JUnit. -->
      <artifactId>junit-jupiter</artifactId>
      <scope>test</scope>
    </dependency>
    <dependency>
      <groupId>org.apache.tomcat.embed</groupId>
      <artifactId>tomcat-embed-core</artifactId>
      <scope>test</scope>
    </dependency>
  </dependencies>
  <!-- Configura as ferramentas e recursos do build. -->
  <build>
    <finalName>restaurante</finalName>
    <resources>
      <resource>
        <directory>src/main/resources</directory>
      </resource>
    </resources>
    <plugins>
      <plugin>
        <groupId>org.apache.maven.plugins</groupId>
        <!-- Empacota os recursos e classes da aplicação web em WAR. -->
        <artifactId>maven-war-plugin</artifactId>
        <configuration>
          <webResources>
            <resource>
              <directory>../contrato/src/main/resources/wsdl</directory>
              <targetPath>WEB-INF/wsdl</targetPath>
            </resource>
          </webResources>
        </configuration>
      </plugin>
    </plugins>
  </build>
</project>

O WAR e seus descritores compõem a borda SOAP. Eles conectam contexto, classes e contrato, mantendo regras no núcleo. A configuração concreta é Metro/Jakarta/Tomcat deste tutorial, não uma reprodução do servidor antigo do livro.
