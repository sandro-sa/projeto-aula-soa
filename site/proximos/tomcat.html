Instalar Tomcat 10.1

Instalar, iniciar e parar o container Servlet que hospedará os serviços..

1. Objetivo da tutorial

Problema no sistema

A versão SOAP será publicada como uma aplicação web Java. Iniciar o Tomcat agora permite confirmar a JVM, a configuração e a porta antes de introduzir o WAR e a conexão ao banco.

Entenda os componentes desta etapa

1. Implementação passo a passo e código da etapa

Passo 1: Verificar a instalação do Java 17

O Apache Tomcat é um servidor de aplicações web Java, utilizado para executar aplicações que implementam tecnologias como Jakarta Servlet e Jakarta Server Pages (JSP).

Antes de instalar o Tomcat, é necessário verificar se o Java está instalado. Neste tutorial, utilizaremos Java 17.

  1. Abra o PowerShell do Windows.
  2. Execute os comandos abaixo:
java -version

javac -version

$env:JAVA_HOME

Explicação dos comandos:

  • java -version: apresenta a versão do Java utilizada pelo terminal.
  • javac -version: mostra a versão do compilador Java.
  • $env:JAVA_HOME: apresenta o caminho configurado para a instalação do JDK.

O resultado deve indicar o Java 17. Se houver outra versão ativa, revise as variáveis JAVA_HOME e Path.

Passo 2: Baixar o Apache Tomcat

  1. Acesse o site oficial: Apache Tomcat 10 Downloads .
  2. Localize a versão estável da série Apache Tomcat 10.1.x.
  3. Na seção Binary Distributions, localize a categoria Core.
  4. Selecione a opção zip, que contém a distribuição binária do Tomcat.
  5. Baixe um arquivo semelhante a: apache-tomcat-10.1.61.zip.
  6. Evite baixar a opção Source Code, pois ela contém o código-fonte e não a distribuição pronta para execução.

Observação: o número da versão pode mudar conforme novas atualizações são publicadas.

Passo 3: Extrair os arquivos

  1. Crie uma pasta para organizar os servidores Java: C:\tomcat.
  2. Acesse a pasta Downloads.
  3. Clique com o botão direito no ZIP e escolha Extrair Tudo.
  4. Extraia a pasta do Tomcat para: C:\tomcat\apache-tomcat-10.1.61.
  5. Verifique se a pasta contém os diretórios bin, conf, lib, logs, temp, webapps e work.

A estrutura da instalação será semelhante a: 

C:\tomcat\
  apache-tomcat-10.1.61\
    bin\
    conf\
    lib\
    logs\
    temp\
    webapps\
    work\
    RUNNING.txt

Função dos principais diretórios:

  • bin: contém os scripts para iniciar, interromper e configurar o Tomcat.
  • conf: contém os arquivos de configuração, incluindo server.xml.
  • lib: contém bibliotecas utilizadas pelo Tomcat.
  • logs: armazena registros de execução e erros.
  • webapps: pasta padrão de publicação das aplicações web.
  • work: armazena arquivos temporários produzidos durante o processamento.

Passo 4: Configurar variáveis de ambiente

A configuração do CATALINA_HOME facilita a localização da instalação do Tomcat. O JAVA_HOME indica qual JDK será utilizado.

  1. No menu Iniciar do Windows, pesquise por "Variáveis de ambiente".
  2. Abra Editar as variáveis de ambiente do sistema.
  3. Clique em Variáveis de Ambiente.
  4. Verifique se JAVA_HOME aponta para o diretório do JDK 17, por exemplo: C:\Java\jdk-17.
  5. Em Variáveis do Sistema, clique em Novo.
  6. Configure:
    • Nome: CATALINA_HOME
    • Valor: C:\tomcat\apache-tomcat-10.1.61
  7. Clique em OK para salvar.

A variável CATALINA_HOME é opcional quando os scripts conseguem identificar automaticamente a instalação. Porém, sua utilização facilita a administração.

Passo 5: Verificar as configurações

Feche o PowerShell e abra uma nova janela. Em seguida, execute: 

$env:JAVA_HOME

$env:CATALINA_HOME

Test-Path "$env:CATALINA_HOME\bin\startup.bat"

Test-Path "$env:CATALINA_HOME\bin\catalina.bat"

Os comandos Test-Path devem retornar True quando os arquivos forem encontrados.

Também podemos consultar a versão do Tomcat: 

& "$env:CATALINA_HOME\bin\version.bat"

O comando deve apresentar informações sobre a versão do servidor, sistema operacional e ambiente Java.

Passo 6: Iniciar o Apache Tomcat

O servidor pode ser iniciado pelo PowerShell utilizando os scripts disponíveis na pasta bin. 

cd "$env:CATALINA_HOME\bin"

.\startup.bat

Explicação:

  • cd: altera o diretório atual do terminal.
  • startup.bat: executa o script responsável por iniciar o servidor.

Alternativamente, para acompanhar a execução diretamente no terminal: 

.\catalina.bat run

Esse comando mantém a execução associada à janela atual, facilitando a visualização das mensagens e dos erros do servidor.

Passo 7: Testar o Tomcat no navegador

  1. Abra o navegador.
  2. Acesse: http://localhost:8080/ .
  3. Verifique se a página inicial do Apache Tomcat aparece.
  4. Se a página estiver disponível, o servidor está respondendo às requisições HTTP.

A porta 8080 é a configuração HTTP padrão do Tomcat.

Passo 8: Verificar a porta 8080

Caso a página não abra, verifique se a porta 8080 está sendo utilizada. 

netstat -ano | findstr :8080

O comando apresenta conexões e processos associados à porta informada.

Para identificar um processo pelo PID: 

Get-Process -Id 1234

Substitua 1234 pelo identificador apresentado no resultado do netstat.

Se outra aplicação estiver ocupando a porta 8080, escolha uma porta livre ou encerre o serviço conflitante de maneira apropriada.

Passo 9: Alterar a porta do Tomcat

Para modificar a porta HTTP, abra o arquivo: 

C:\tomcat\apache-tomcat-10.1.61\conf\server.xml

Localize o conector HTTP, que poderá ser semelhante a: 

<Connector port="8080"
           protocol="HTTP/1.1"
           connectionTimeout="20000" />

Para utilizar a porta 8081, altere somente o atributo port: 

<Connector port="8081"
           protocol="HTTP/1.1"
           connectionTimeout="20000" />

Salve o arquivo e reinicie o Tomcat. O endereço passará a ser: 

http://localhost:8081/

Passo 10: Encerrar o Apache Tomcat

Se o servidor foi iniciado utilizando startup.bat, execute: 

& "$env:CATALINA_HOME\bin\shutdown.bat"

Se estiver utilizando catalina.bat run, pressione Ctrl+C na janela do terminal para solicitar o encerramento.

Aguarde a finalização do processo antes de iniciar outra instância.

Passo 11: Resolver problemas comuns

startup.bat não foi encontrado

Confirme se a pasta bin existe e se CATALINA_HOME aponta para a raiz correta da instalação.

JAVA_HOME não foi definido

Configure JAVA_HOME apontando para a pasta do JDK 17. Abra um novo terminal e tente novamente.

Porta 8080 já está sendo utilizada

Verifique se existe outro Tomcat ou servidor executando na mesma porta. Altere a porta HTTP ou encerre a instância conflitante.

Erro HTTP 404

Verifique o nome do WAR, o contexto da aplicação, o caminho do endpoint e as mensagens de publicação.

Erro HTTP 500

Consulte os logs do Tomcat. O problema pode estar no código, nas dependências, na configuração da aplicação ou na conexão com o banco.

O Eclipse não mostra o menu Server

Instale o Eclipse Web Tools Platform e os adaptadores de servidor ou utilize a edição Enterprise Java and Web Developers.

Erro de compatibilidade javax/jakarta

O Tomcat 10.1 utiliza APIs Jakarta. Aplicações antigas baseadas em javax.servlet podem exigir migração. Verifique as versões das bibliotecas utilizadas pelo projeto.

Observações importantes

O Tomcat será responsável por executar as aplicações Java SOAP e REST empacotadas em WAR.

O XAMPP será utilizado separadamente para disponibilizar o MariaDB e o phpMyAdmin.

O Maven gerencia dependências e automatiza a compilação, os testes e o empacotamento.

O Eclipse será utilizado para desenvolver, depurar e administrar os projetos.

Este tutorial utiliza o Tomcat em ambiente local de desenvolvimento. Antes de disponibilizar aplicações na internet, é necessário realizar configurações adicionais de segurança.
