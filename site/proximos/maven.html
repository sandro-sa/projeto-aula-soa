Instalar Maven e compreender o POM

Entender coordenadas, escopos, reator, plugins e resolução de dependências.

1. Objetivo do tutorial

Entender coordenadas, escopos, reator, plugins e resolução de dependências.

2. Conceitos necessários

Problema no sistema

Cada aluno precisa obter as mesmas dependências e executar as fases de build na ordem correta. O Maven lê a configuração do POM e oferece uma forma repetível de construir o projeto.

Entenda os componentes desta etapa
ParteO que faz e por que importa
MAVEN_HOME e PathIdentificam a instalação e permitem encontrar mvn na pasta bin quando o comando é digitado.
mvn -versionMostra a instalação Maven e o Java realmente usados por essa execução.
pom.xml e coordenadasIdentificam o projeto e descrevem suas dependências, plugins e tipo de artefato.
compile, test, package e verifyCompilam, executam testes, produzem o artefato ou percorrem o build até as verificações configuradas.
repositório localGuarda bibliotecas e plugins resolvidos. Os módulos do próprio laboratório também podem participar juntos do mesmo build Maven.

Maven automatiza o ciclo de build e resolve artefatos a partir de um Project Object Model (POM). O POM descreve o projeto; não é uma lista arbitrária de JARs.

Maven lê o POM e executa o ciclo de build. groupId identifica o grupo, artifactId identifica o módulo e version identifica a versão. Dependências fornecem APIs/bibliotecas; plugins executam tarefas como compilar e empacotar. Um POM organiza versões compatíveis sem adicionar todas as bibliotecas ao projeto.

compile participa da compilação e execução; runtime é necessário para executar, como Connector/J; provided é fornecido pelo container, como Servlet no Tomcat; test fica restrito aos testes, como JUnit e H2. JAR distribui classes; WAR inclui recursos e descritores para um container; packaging pom agrega módulos.

Instale o binário do Maven pelo site oficial, extraia e adicione a pasta bin ao PATH. Use Maven Central para localizar coordenadas e a documentação oficial para confirmar compatibilidade. Neste ponto apenas verifique a ferramenta: não há POM para executar clean install.

Mais adiante, dependency:tree mostrará dependências transitivas; effective-pom mostrará o resultado da herança. Não resolva conflitos copiando JARs para Eclipse ou Tomcat.

5. Implementação passo a passo e código da etapa

Passo 1: Verificar se o Java está instalado

O Apache Maven é uma ferramenta de automação de compilação e gerenciamento de dependências para projetos Java. Para funcionar, é necessário ter um JDK instalado. Neste tutorial, utilizaremos o Java 17.

  1. Abra o PowerShell do Windows.
  2. Execute o comando abaixo para verificar a instalação do Java.
java -version
javac -version

Os comandos devem apresentar a versão instalada do Java. Se o Java não estiver disponível, instale e configure o JDK 17 antes de continuar.

Passo 2: Baixar o arquivo ZIP do Maven

  1. Acesse o site oficial do Apache Maven: https://maven.apache.org/download.cgi
  2. Localize a seção de downloads da versão estável do Apache Maven.
  3. Procure pela opção Binary zip archive.
  4. Baixe o arquivo ZIP, por exemplo: apache-maven-3.10.0-bin.zip.
  5. Não selecione o arquivo Source zip archive, pois ele contém o código-fonte do Maven, não a distribuição binária pronta para uso.

Passo 3: Extrair os arquivos

  1. Crie uma pasta para organizar as ferramentas de desenvolvimento, por exemplo: C:\Meus_programas\.
  2. Clique com o botão direito no arquivo ZIP baixado e selecione Extrair Tudo.
  3. Extraia a distribuição do Maven para a pasta criada.
  4. O caminho final poderá ser: C:\Meus_programas\apache-maven-3.10.0.
  5. Verifique se dentro dessa pasta existe o diretório bin, contendo o arquivo mvn.cmd.

Passo 4: Configurar as variáveis de ambiente

Como o arquivo ZIP não possui instalador automático, é necessário configurar o Windows para localizar o Maven pelo terminal.

  1. No menu Iniciar do Windows, digite Variáveis de ambiente.
  2. Clique em Editar as variáveis de ambiente do sistema.
  3. Na janela aberta, clique em Variáveis de Ambiente....
  4. Em Variáveis do Sistema, clique em Novo....
  5. Crie a variável de ambiente do Maven:
    1. Nome da variável: MAVEN_HOME
    2. Valor da variável: C:\Meus_programas\apache-maven-3.10.0
    3. Clique em OK.
  6. Ainda em Variáveis do Sistema, localize a variável Path e clique em Editar....
  7. Clique em Novo e adicione: %MAVEN_HOME%\bin
  8. Verifique se a variável JAVA_HOME aponta para a pasta do JDK 17, sem incluir o diretório bin.
  9. Clique em OK em todas as janelas para salvar.

Passo 5: Testar a instalação do Maven

Feche o PowerShell e abra uma nova janela para carregar as variáveis de ambiente. 

mvn -version

Ou utilize:

mvn -v

O resultado deverá mostrar informações semelhantes às seguintes: 

Apache Maven 3.10.0
Maven home: C:\Meus_programas\apache-maven-3.10.0
Java version: 17
OS name: "windows"

Verifique especialmente se o Maven está utilizando o Java 17 configurado para o projeto.

Passo 6: Verificar as variáveis de ambiente

No PowerShell, execute os comandos abaixo para conferir as configurações. 

$env:JAVA_HOME
$env:MAVEN_HOME

where.exe java
where.exe mvn

O comando where.exe mvn deve localizar o executável do Maven dentro da pasta bin.

Passo 7: Testar o Maven em um projeto Java

Abra o PowerShell na pasta de um projeto que contenha o arquivo pom.xml.

Por exemplo, para acessar o projeto restaurante SOAP: 

cd C:\workspace\Java\restaurante-soap

mvn validate

mvn clean package

O comando mvn validate verifica se o projeto possui uma configuração Maven válida.

O comando mvn clean package limpa os arquivos gerados anteriormente, compila o projeto, executa os testes configurados e gera o pacote da aplicação.

Dependendo da configuração do pom.xml, o resultado poderá ser um arquivo .jar ou .war.

Como resolver problemas comuns?

Erro: mvn não é reconhecido

Verifique se a variável MAVEN_HOME aponta para a pasta correta e se %MAVEN_HOME%\bin está no Path. Abra um novo terminal após as alterações.

Erro: JAVA_HOME não está configurado

Configure JAVA_HOME com o caminho do JDK 17. Não inclua a pasta bin no valor dessa variável.

O Maven está usando outra versão do Java

Execute mvn -version e confira a linha Java version. Se estiver incorreta, revise JAVA_HOME e a ordem dos diretórios Java presentes no Path.

6. Explicação do código e das decisões

  • O pai define release, codificação, POM e versões de plugins; cada filho declara somente suas necessidades.
  • O servidor usa provided para Servlet e inclui o runtime Metro; o WAR não carrega H2.
  • wsimport lê contratos locais, gera 72 arquivos Java em target e os compila no mesmo build.
  • install permite que exec:java no desktop encontre contrato e núcleo já construídos.

10. Problemas frequentes

  • Erro de pacote: compare a declaração package com a pasta src/main/java.
  • Dependência não resolvida: confirme o POM e o módulo criados nesta etapa; não copie JARs manualmente.
  • Não execute um tutorial posterior para compensar um erro: retorne ao último checkpoint aprovado.
