Publicar o SOAP no Tomcat localhost

Publicar o projeto servidor no Tomcat configurado no Eclipse e abrir um WSDL.

1. O que fazer nesta etapa

Publicar o projeto servidor no Tomcat configurado no Eclipse e abrir um WSDL.

Esta aula é uma atividade de execução, análise ou registro sobre o sistema já construído.

A aula termina quando: O Tomcat inicia e o WSDL de mesas é acessível com a identidade autorizada.

Continue no Eclipse após Registrar filtros e serviços no Tomcat. Use os projetos e os arquivos que você construiu nas etapas anteriores.

2. Entenda o que será feito

Problema no sistema

O WAR pronto ainda precisa ser associado à instância do Tomcat e receber sua configuração de execução. Esta etapa verifica que o serviço publica um WSDL acessível no endereço esperado.

Entenda os componentes desta etapa
ParteO que faz e por que importa
Targeted RuntimesLiga o projeto web ao Tomcat registrado no Eclipse.
Web Project SettingsDefine o contexto restaurante, que entra antes das rotas /soap e /api/public.
EnvironmentEntrega ao processo do servidor a URL do banco, as credenciais e a base pública usada pelo QR.
Servers, Add and Remove e PublishAssociam o módulo à instância e sincronizam os recursos que o Tomcat executará.
Console e ?wsdlA Console confirma o início do contexto. A leitura do WSDL após autenticação confirma endereço, publicação e transporte SOAP.

Compilar o WAR e iniciar o Tomcat são ações distintas. O listener precisa de banco e credenciais válidos para concluir a inicialização.

  • Use a instância Tomcat já registrada na aba Servers.
  • Registre URL, estado do servidor e resultado, sem senhas.
Pontos para observar no código
  • DB_URL escolhe o banco de cada implementação; DB_USER e DB_PASSWORD não entram no artefato.
  • PUBLIC_BASE_URL define o destino do QR, não a porta em que o servidor escuta.
  • PORT altera a porta REST; a porta SOAP é configurada no conector Tomcat.

3. Faça o passo a passo

Passo 1: Verificar pelo Maven no Eclipse

  1. Use File → Save All.
  2. No projeto restaurante-soap, clique com o botão direito e escolha Run As → Maven build…. Use um nome identificável, como Verificar aula 51.
  3. Confira Base directory: selecione o projeto restaurante-soap com Browse Workspace…. Em Goals, informe o conteúdo abaixo, sem o prefixo mvn.
  4. Na aba JRE, confira o JDK 17. Clique em Apply → Run e acompanhe a aba Console.
package

Confira: a execução deve terminar em BUILD SUCCESS. Esse checkpoint valida o build desta etapa; a inicialização com banco e a interação pelas telas serão conferidas nas aulas de execução.

Passo 2: Publicar e conferir o WSDL

  1. Confira se o MySQL está em execução e se o banco restaurante_soap e seu usuário foram preparados nas aulas iniciais.
  2. No projeto servidor, abra Properties → Targeted Runtimes e selecione o Tomcat 10.1 registrado no Eclipse.
  3. Em Properties → Web Project Settings, confira o contexto restaurante.
  4. Na aba Servers, dê dois cliques no Tomcat e abra sua configuração de execução pelo link Open launch configuration. Preencha a aba Environment conforme a tabela.
  5. Com o Tomcat parado, use Add and Remove… na aba Servers para adicionar o projeto servidor. Depois use Publish e Start.
  6. Leia a Console: a inicialização de Contexto/Flyway precisa concluir. Abra o endereço WSDL abaixo no navegador e forneça a identidade configurada quando solicitado.

Na aba Environment da configuração de execução, use New… para fornecer:

VariávelValor no seu ambiente
DB_URLjdbc:mysql://localhost:3306/restaurante_soap?connectionTimeZone=UTC
DB_USERO usuário do banco criado no laboratório, por exemplo restaurante.
DB_PASSWORDA senha definida para esse usuário.
RESTAURANTE_ADMIN_PASSWORDUma senha de laboratório para admin, com pelo menos 12 caracteres.
RESTAURANTE_GARCOM_PASSWORDOutra senha de pelo menos 12 caracteres, diferente da senha admin.
PUBLIC_BASE_URLhttp://localhost:8080/restaurante

Os valores reais ficam na sua configuração local. No registro de atividades, anote apenas os nomes das variáveis e o resultado da verificação.

http://localhost:8080/restaurante/soap/mesas?wsdl

Confira: resposta XML do WSDL. Um 401 pede conferir a identidade; um 404 pede conferir publicação, contexto e rota. Para o SOAP, o endpoint usa /soap/mesas.

Registre a verificação no arquivo docs/registro-laboratorio.md. No projeto laboratorio-restaurante, use New → File se ele ainda não existir; nas próximas atividades, acrescente a nova aula ao mesmo registro.

4. Resultado esperado

O Tomcat inicia e o WSDL de mesas é acessível com a identidade autorizada.

Se a verificação não der certo
  • Leia a mensagem específica na Console ou na aba Problems; confira o projeto, o caminho do arquivo e o pacote.
  • Depois de mudar POMs, use Maven → Update Project…. Confira se cada módulo listado já possui seu POM.
  • No Maven build, confira Base directory, Goals e o JDK 17. Em erro de download, confira a conexão e o repositório informado.
  • Em problema de execução, diferencie configuração do processo, conexão com o banco, rota/contrato e regra de negócio. Consulte a aula de diagnóstico.
