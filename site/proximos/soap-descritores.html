2. Entenda o que será feito

Problema no sistema

O Tomcat precisa saber quais classes inicia e quais requisições entrega a cada componente. Os descritores conectam as rotas aos endpoints, ao filtro de autenticação e ao cardápio público.

Os descritores ligam listeners, filtro, Servlet e endpoints às URLs; a configuração externa fornece as credenciais do processo.

  • As rotas são /soap/mesas, /soap/categorias, /soap/produtos e /soap/pedidos.
  • configurar-sessao.ps1 é uma alternativa para execução por terminal; no Eclipse, use a aba Environment da configuração do Tomcat.
Pontos para observar no código
  • O listener precisa terminar com banco/configuração válidos antes das requisições.
  • Servlet e endpoint mappings precisam concordar com os caminhos dos WSDLs.
  • O script de sessão configura DB_URL com MySQL localhost:3306; não guarda senhas em arquivo.

Passo 2: Criar web.xml

Caminho na pasta do laboratório: source/restaurante-soap/servidor/src/main/webapp/WEB-INF/web.xml.

  1. No projeto servidor, selecione a pasta src/main/webapp/WEB-INF. Para preparar o caminho, use New → Folder a partir da raiz e informe as pastas que faltarem.
  2. Use File → New → Other… → General → File, informe web.xml e confira o diretório de destino.
  3. Abra o arquivo no editor de texto/código do Eclipse e salve em UTF-8. Para XML e POM, selecione a aba de fonte do editor quando houver uma visão de formulário.

Os comentários do código explicam os blocos e podem ser copiados junto com o arquivo. Salve com Ctrl+S.

<?xml version="1.0" encoding="UTF-8"?>
<!-- Finalidade: Criar os descritores web.xml e sun-jaxws.xml e conferir a configuração de execução. -->
<web-app xmlns="https://jakarta.ee/xml/ns/jakartaee" version="6.0">
  <listener>
    <listener-class>br.edu.soa.restaurante.Contexto</listener-class>
  </listener>
  <listener>
    <listener-class>com.sun.xml.ws.transport.http.servlet.WSServletContextListener</listener-class>
  </listener>
  <filter>
    <filter-name>autenticacao</filter-name>
    <filter-class>br.edu.soa.restaurante.AutenticacaoFilter</filter-class>
  </filter>
  <filter-mapping>
    <filter-name>autenticacao</filter-name>
    <url-pattern>/soap/*</url-pattern>
  </filter-mapping>
  <servlet>
    <servlet-name>soap</servlet-name>
    <servlet-class>com.sun.xml.ws.transport.http.servlet.WSServlet</servlet-class>
    <load-on-startup>1</load-on-startup>
  </servlet>
  <servlet-mapping>
    <servlet-name>soap</servlet-name>
    <url-pattern>/soap/*</url-pattern>
  </servlet-mapping>
  <servlet>
    <servlet-name>cardapio</servlet-name>
    <servlet-class>br.edu.soa.restaurante.CardapioServlet</servlet-class>
  </servlet>
  <servlet-mapping>
    <servlet-name>cardapio</servlet-name>
    <url-pattern>/api/public/*</url-pattern>
  </servlet-mapping>
  <security-role>
    <role-name>ADMIN</role-name>
  </security-role>
  <security-role>
    <role-name>GARCOM</role-name>
  </security-role>
</web-app>

<?xml version="1.0" encoding="UTF-8"?>
<!-- Finalidade: Criar os descritores web.xml e sun-jaxws.xml e conferir a configuração de execução. -->
<endpoints xmlns="http://java.sun.com/xml/ns/jax-ws/ri/runtime" version="2.0">
  <endpoint name="MesaService" implementation="br.edu.soa.restaurante.MesaEndpoint" wsdl="WEB-INF/wsdl/MesaService.wsdl" service="{http://restaurante.soa.edu.br/v2}MesaService" port="{http://restaurante.soa.edu.br/v2}MesaPort" url-pattern="/soap/mesas"/>
  <endpoint name="CategoriaService" implementation="br.edu.soa.restaurante.CategoriaEndpoint" wsdl="WEB-INF/wsdl/CategoriaService.wsdl" service="{http://restaurante.soa.edu.br/v2}CategoriaService" port="{http://restaurante.soa.edu.br/v2}CategoriaPort" url-pattern="/soap/categorias"/>
  <endpoint name="ProdutoService" implementation="br.edu.soa.restaurante.ProdutoEndpoint" wsdl="WEB-INF/wsdl/ProdutoService.wsdl" service="{http://restaurante.soa.edu.br/v2}ProdutoService" port="{http://restaurante.soa.edu.br/v2}ProdutoPort" url-pattern="/soap/produtos"/>
  <endpoint name="PedidoService" implementation="br.edu.soa.restaurante.PedidoEndpoint" wsdl="WEB-INF/wsdl/PedidoService.wsdl" service="{http://restaurante.soa.edu.br/v2}PedidoService" port="{http://restaurante.soa.edu.br/v2}PedidoPort" url-pattern="/soap/pedidos"/>
</endpoints>

  2. Use File → New → Other… → General → File, informe configurar-sessao.ps1 e confira o diretório de destino.

Os comentários do código explicam os blocos e podem ser copiados junto com o arquivo. Salve com Ctrl+S.

# Finalidade: Criar os descritores web.xml e sun-jaxws.xml e conferir a configuração de execução.
param([ValidateSet('soap','rest')][string]$Protocolo = 'soap')
$ErrorActionPreference = 'Stop'
$env:DB_URL = "jdbc:mysql://localhost:3306/restaurante_${Protocolo}?connectionTimeZone=UTC"
$env:DB_USER = 'restaurante'
$env:DB_PASSWORD = [System.Net.NetworkCredential]::new('', (Read-Host 'Senha do banco' -AsSecureString)).Password
$env:RESTAURANTE_ADMIN_PASSWORD = [System.Net.NetworkCredential]::new('', (Read-Host 'Senha ADMIN (mínimo 12 caracteres)' -AsSecureString)).Password
$env:RESTAURANTE_GARCOM_PASSWORD = [System.Net.NetworkCredential]::new('', (Read-Host 'Senha GARCOM (distinta, mínimo 12 caracteres)' -AsSecureString)).Password
$env:PUBLIC_BASE_URL = if ($Protocolo -eq 'soap') { 'http://localhost:8080/restaurante' } else { 'http://localhost:8081' }
Write-Host 'Variáveis configuradas somente neste terminal. Para celular, ajuste PUBLIC_BASE_URL para o IP acessível.'

Confira: o arquivo está no projeto agregador, no caminho indicado e com o conteúdo completo desta etapa.

Entenda cada parte de configurar-sessao.ps1
ParteO que faz e por que importa
param e ValidateSetSelecionam SOAP ou REST e limitam o protocolo aos valores previstos pelo roteiro.
DB_URL, DB_USER e DB_PASSWORDConfiguram conexão e credenciais do banco do processo a iniciar. O sufixo distingue os esquemas SOAP e REST.
Read-Host -AsSecureStringSolicita as senhas sem ecoar a digitação. A configuração resultante fica nas variáveis do processo e de seus filhos.
PUBLIC_BASE_URLIndica a origem usada para montar o endereço do cardápio no QR. O SOAP inclui o contexto do WAR.
Environment no EclipsePara iniciar pela IDE, configure esses mesmos valores no lançamento que iniciará Tomcat ou Spring Boot.
