2. Entenda o que será feito

Problema no sistema

Uma edição no catálogo precisa chegar ao caso de uso com os campos da categoria e o papel correto. O endpoint de categorias concentra essa adaptação para SOAP.

O endpoint de categoria autoriza a chamada, delega a Restaurante e converte o resultado pelo contrato.

  • Confira endpointInterface, serviceName e portName contra o WSDL.
  • WebServiceContext fornece o contexto usado para conferir o papel.
Pontos para observar no código
  • @WebService declara CategoriaService e CategoriaPort exatamente como o WSDL.
  • @Resource fornece o contexto da chamada para autorizar o papel.
  • SoapDtos converte o resultado; ErroNegocio_Exception é parte do contrato.

// Finalidade: Adaptar o contrato SOAP aos casos de uso e aos tipos de resposta.
package br.edu.soa.restaurante;
import br.edu.soa.restaurante.soap.*;
import jakarta.jws.WebService;
import jakarta.annotation.Resource;
import jakarta.xml.ws.WebServiceContext;
@WebService(endpointInterface="br.edu.soa.restaurante.soap.CategoriaServicePortType", serviceName="CategoriaService", portName="CategoriaPort", targetNamespace="http://restaurante.soa.edu.br/v2", wsdlLocation="WEB-INF/wsdl/CategoriaService.wsdl")
public class CategoriaEndpoint implements CategoriaServicePortType {
 @Resource private WebServiceContext contexto;
 @Override public Categoria criarCategoria(CategoriaEntrada v) throws ErroNegocio_Exception {
  return Acesso.executar(contexto, true, () -> { var api=Contexto.restaurante(); if(v==null) throw br.edu.soa.restaurante.aplicacao.Falha.invalido("Informe categoria."); return SoapDtos.dto(api.salvarCategoria(0, v.getNome(), v.getDescricao(), v.isAtivo())); });
 }
 @Override public Categoria consultarCategoria(long id) throws ErroNegocio_Exception {
  return Acesso.executar(contexto, false, () -> { var api=Contexto.restaurante(); return SoapDtos.dto(api.consultarCategoria(id)); });
 }
 // Autoriza a operação SOAP e delega aos casos de uso de Restaurante.
 @Override public java.util.List<Categoria> listarCategorias() throws ErroNegocio_Exception {
  return Acesso.executar(contexto, false, () -> { var api=Contexto.restaurante(); return api.listarCategorias().stream().map(SoapDtos::dto).toList(); });
 }
 @Override public Categoria atualizarCategoria(long id, CategoriaEntrada v) throws ErroNegocio_Exception {
  return Acesso.executar(contexto, true, () -> { var api=Contexto.restaurante(); if(id<=0 || v==null) throw br.edu.soa.restaurante.aplicacao.Falha.invalido("ID positivo e dados obrigatórios."); return SoapDtos.dto(api.salvarCategoria(id, v.getNome(), v.getDescricao(), v.isAtivo())); });
 }
 // Autoriza a operação SOAP e delega aos casos de uso de Restaurante.
 @Override public boolean excluirCategoria(long id) throws ErroNegocio_Exception {
  return Acesso.executar(contexto, true, () -> { var api=Contexto.restaurante(); api.excluirCategoria(id); return true; });
 }
}

Entenda cada parte de CategoriaEndpoint.java

Módulo servidor · Pacote br.edu.soa.restaurante · Fontes src/main/java.

ParteO que faz e por que importa
@WebServiceVincula a classe à interface gerada, ao nome de serviço, à porta, ao namespace e ao WSDL empacotado.
implements CategoriaServicePortTypeMantém as assinaturas de operações e a exceção declaradas pelo contrato SOAP.
@Resource WebServiceContextRecebe do runtime o contexto usado para verificar o papel da chamada.
operações de leituraConsulta e listagem entregam categorias convertidas para os tipos do WSDL.
operações de escritaCriação e atualização leem nome, descrição e ativo do DTO. Cadastro, alteração e exclusão exigem ADMIN.
Acesso.executar, Contexto e SoapDtosConferem o papel, obtêm os casos de uso e convertem o resultado para o tipo do contrato. As regras de negócio são executadas por Restaurante.

Fundamentação nos PDFs fornecidos

O endpoint de Categoria implementa a interface do WSDL, valida o papel e traduz os dados. As regras permanecem em Restaurante e o SQL em JdbcRepositorio; trocar o adaptador não deve duplicar essas regras.

  • [R03] Robert C. Martin — Arquitetura Limpa: o guia do artesão para estrutura e design de software. Cap. 22: regra de dependência e adaptadores. Páginas 273–282 do PDF.
