Projeto SOAP|OpenAPI

Construir, executar e compreender o mesmo sistema com SOAP e REST/OpenAPI.

1. Objetivo

Construir, executar e compreender o mesmo sistema com SOAP e REST/OpenAPI.

2. Conceitos necessários

Java básico, classes, exceções, coleções e uma primeira noção de cliente/servidor. Cada parte avançada será introduzida antes do código.

Comece em uma pasta vazia chamada laboratorio-restaurante-soa. Nesta trilha você criará os POMs, pacotes, classes, contratos, banco, telas e páginas Web.

Cada página trata de um assunto e mostra o estado do arquivo naquela etapa. Quando uma classe crescer, o código completo da nova versão será apresentado e explicado. Os comandos só serão usados depois que os arquivos dos quais dependem tiverem sido construídos. O Spring Initializr fornece apenas a estrutura inicial da parte REST; os recursos do restaurante serão implementados depois.

  1. Preparar Java, Eclipse, Maven, MySQL e Tomcat.
  2. Criar o projeto Maven e o domínio, classe por classe.
  3. Implementar regras e persistência, depois contratos e endpoints SOAP.
  4. Construir as telas Swing e o cardápio.
  5. Gerar uma aplicação vazia no Spring Initializr e implementar REST/OpenAPI.
  6. Executar os testes e os dois sistemas em localhost.

O destino final é um laboratório local: SOAP em localhost:8080/restaurante e REST em localhost:8081, com bancos MySQL distintos. Não é necessário publicar nada na Internet.

3. Problema que será resolvido

Organizar uma construção reproduzível sem exigir nenhum arquivo funcional como ponto de partida.

Fundamentação

Os serviços são capacidades do restaurante e os frameworks são ferramentas para expô-las. A construção começa na pasta vazia; os livros orientam as decisões, não fornecem um projeto do restaurante para importar.

6. Como implementar no Eclipse e executar

  1. Continue na pasta do aluno criada no tutorial inicial. Não importe a solução final.
  2. Execute a configuração/experimento descrito acima e registre o resultado.
  3. Execute somente os comandos desta página. Use outro terminal quando um comando mantiver um servidor em execução.
$pastaLaboratorio = Join-Path $env:USERPROFILE 'laboratorio-restaurante-soa'
if (Test-Path $pastaLaboratorio) { throw 'Escolha outra pasta vazia para iniciar a atividade.' }
New-Item -ItemType Directory -Path $pastaLaboratorio
Set-Location $pastaLaboratorio
Get-ChildItem -Force

7. Fluxo da execução

Pasta vazia → ferramentas → POM inicial → arquivos escritos por assunto → testes → localhost.

8. Resultado esperado nesta etapa

Somente uma pasta vazia foi criada; ainda não existe aplicação para executar.

O resultado é um checkpoint para você executar. O registro de validação do material distingue testes automatizados, reconstrução da trilha e execução real no MySQL. Consulte também a revisão passo a passo dos HTMLs.

9. Problemas frequentes

  • Pasta já existe: escolha outro nome vazio, preservando o trabalho anterior.
  • Permissão negada: use uma pasta gravável do seu perfil, sem exigir execução como administrador.
  • Diretório errado: confirme Get-Location antes de criar os primeiros arquivos.
