2. Entenda o que será feito

Categoria agrupa produtos; uma mesa tem pedidos ao longo do tempo; cada pedido reúne itens que preservam nome e preço da inclusão.

  • Total e subtotal são calculados; não são valores escolhidos pelo cliente.
  • O teste Maven desta etapa percorre o ciclo do domínio; ainda não criamos testes JUnit nesse módulo.
Pontos para observar no código
  • O construtor compacto de Pedido copia itens e impede mutação externa.
  • subtotal() não recebe preço do cliente; usa o preço unitário armazenado no item.
  • total() percorre os itens e soma com BigDecimal.add.
  • Enums restringem estados e tornam transições legíveis.

# Modelo de Entidades — Restaurante

## Objetivo

Apresentar os relacionamentos entre as entidades
do sistema de restaurante SOAP e REST.

## Diagrama de entidades

```mermaid
erDiagram
    MESA ||--o{ PEDIDO : recebe
    CATEGORIA ||--o{ PRODUTO : classifica
    PEDIDO ||--o{ ITEM_PEDIDO : contem
    PRODUTO ||--o{ ITEM_PEDIDO : referencia

    MESA {
        bigint id PK
        int numero UK
        string situacao
    }

    CATEGORIA {
        bigint id PK
        string nome
        string descricao
        boolean ativo
    }

    PRODUTO {
        bigint id PK
        bigint categoria_id FK
        string nome
        decimal preco
    }

    PEDIDO {
        bigint id PK
        bigint mesa_id FK
        timestamp data_hora
        string situacao
    }

    ITEM_PEDIDO {
        bigint id PK
        bigint pedido_id FK
        bigint produto_id FK
        int quantidade
        decimal preco_unitario
    }
```

## Explicação dos relacionamentos

### Mesa e Pedido
Uma mesa pode receber vários pedidos ao longo do tempo.

### Categoria e Produto
Uma categoria pode classificar vários produtos.

### Pedido e ItemPedido
Um pedido pode conter vários itens.

### Produto e ItemPedido
Um produto pode aparecer em vários itens de pedidos.

## Conceitos importantes

- PK: chave primária.
- FK: chave estrangeira.
- UK: chave única.
- 1:N: relacionamento de um para muitos.

Passo 3: Verificar o projeto pelo Maven no Eclipse

Nesta etapa, vamos verificar se as classes Java do módulo dominio continuam compilando corretamente após a documentação do modelo de entidades.

Importante: o Maven verifica o projeto Java, mas não valida automaticamente o conteúdo do arquivo entidades.md. A conferência do diagrama será realizada no próximo passo.

3.1. Salvar os arquivos

  1. No Eclipse, selecione File → Save All.
  2. Confira se o arquivo diagramas/entidades.md está salvo.
  3. Verifique se as classes Java das aulas anteriores estão presentes no módulo dominio.

3.2. Executar a verificação Maven

  1. Na janela Project Explorer, localize o projeto dominio.
  2. Clique com o botão direito sobre o projeto.
  3. Selecione Run As → Maven build….
  4. No campo Name, informe Verificar aula 19.
  5. Em Base directory, clique em Browse Workspace… e selecione o projeto dominio.
  6. No campo Goals, informe o comando apresentado abaixo, sem o prefixo mvn.
  7. Na aba JRE, confira se o ambiente utiliza o JDK 17.
  8. Clique em Apply → Run.

Goal do Maven:

test

Esse goal executa as fases necessárias do ciclo de vida do Maven até a fase de testes, incluindo a compilação das classes Java e dos testes.

3.3. Interpretar o resultado

Na janela Console, observe as mensagens apresentadas pelo Maven.

Se a execução terminar corretamente, deverá aparecer a mensagem: 

[INFO] BUILD SUCCESS

Se houver algum problema de compilação, dependência ou teste, poderá aparecer: 

[INFO] BUILD FAILURE

Atenção: a mensagem BUILD SUCCESS confirma a conclusão da execução Maven, mas não garante que existam testes automatizados nem que o diagrama Mermaid esteja correto.

Caso existam testes JUnit configurados, consulte os relatórios em target/surefire-reports e verifique quantos testes foram executados, aprovados, ignorados ou apresentaram falhas.
