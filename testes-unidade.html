2. Entenda o que será feito

Problema no sistema

Um preço inválido ou uma quantidade zero deve ser rejeitado antes de abrir uma transação. O teste confirma tanto a recusa quanto a ausência de chamadas ao repositório.

JUnit verifica as recusas e Mockito permite conferir que uma entrada inválida foi barrada antes de acessar o repositório.

  • assertThrows confere a exceção esperada.
  • verifyNoInteractions verifica que a persistência não foi chamada.
Pontos para observar no código
  • assertThrows verifica a recusa, não apenas ausência de retorno.
  • verifyNoInteractions demonstra que quantidade/preço/imagem inválidos não chegam à infraestrutura.
  • Dependências test não entram no JAR de produção.

// Finalidade: Verificar os cenários desta etapa por asserções automatizadas.
package br.edu.soa.restaurante.aplicacao;

import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.*;
import static org.mockito.Mockito.*;
import java.math.BigDecimal;

class RestauranteTest {
    // Cenário: rejeita quantidade antes de acessar repositorio.
    @Test void rejeitaQuantidadeAntesDeAcessarRepositorio() {
        Repositorio repo=mock(Repositorio.class); Restaurante api=new Restaurante(repo);
        assertThrows(Falha.class,() -> api.adicionarItem(1,1,0));
        assertThrows(Falha.class,() -> api.atualizarQuantidadeItem(1,1,-1));
        verifyNoInteractions(repo);
    }
    // Cenário: rejeita preco negativo ou fracionario.
    @Test void rejeitaPrecoNegativoOuFracionario() {
        Repositorio repo=mock(Repositorio.class); Restaurante api=new Restaurante(repo);
        for(String v:new String[]{"-0.01","1.001","10000000.00"})
            assertThrows(Falha.class,() -> api.salvarProduto(0,1,"Suco","","",new BigDecimal(v),"1 copo",true));
        verifyNoInteractions(repo);
    }
    // Cenário: rejeita imagem com protocolo executavel ou caminho local.
    @Test void rejeitaImagemComProtocoloExecutavelOuCaminhoLocal() {
        Repositorio repo=mock(Repositorio.class); Restaurante api=new Restaurante(repo);
        for(String imagem:new String[]{"javascript:alert(1)","file:///C:/privado.png","assets/../segredo.png"})
            assertThrows(Falha.class,() -> api.salvarProduto(0,1,"Suco","",imagem,BigDecimal.ONE,"1 copo",true));
        verifyNoInteractions(repo);
    }
}

Confira: o arquivo pertence ao projeto aplicacao, no caminho indicado e com o conteúdo completo desta etapa.

Entenda cada parte de RestauranteTest.java

Módulo aplicacao · Pacote br.edu.soa.restaurante.aplicacao · Fontes src/test/java.

Parte O que faz e por que importa
@Test e src/test/java Identificam cenários executados pelo JUnit durante a fase test. Cada método descreve um comportamento observado.
mock(Repositorio.class) Cria um substituto da porta de persistência e permite executar as regras sem preparar o MySQL.
rejeitaQuantidadeAntesDeAcessarRepositorio Exercita adição com zero e alteração com quantidade negativa.
rejeitaPrecoNegativoOuFracionario Exercita preço negativo, fração de centavo e preço acima do máximo.
rejeitaImagemComProtocoloExecutavelOuCaminhoLocal Exercita URI executável, arquivo local e caminho de recurso que tenta subir de diretório.
assertThrows e verifyNoInteractions A primeira asserção verifica que uma Falha foi lançada. A segunda confirma que a regra interrompeu a execução antes da persistência.
